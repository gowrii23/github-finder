**Prompt:** Two AI models answered "What is the difference between precision and recall?"

**Answer A:**

**Answer B:**

**Write your evaluation:**

<details>
<summary>Gold-standard answer (click to reveal)</summary>

**What was asked:** Compare two explanations of precision vs recall.

**Answer A analysis:**
- Strength: Provides correct mathematical definitions (TP/TP+FP for precision, TP/TP+FN for recall). Distinguishes clearly between the two concepts with plain-language interpretations.

### Mock Q2: Code Bug Finding (Coding + Writing)

**Prompt:** Find all bugs in this code and explain.

```python
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split
import pandas as pd

df = pd.read_csv("data.csv")
X = df.drop("target", axis=1)
y = df["target"]

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

X_train, X_test, y_train, y_test = train_test_split(X_scaled, y, test_size=0.2)

model = LogisticRegression()
model.fit(X_train, y_train)
print("Accuracy:", model.score(X_train, y_train))
```

<details>
<summary>Gold-standard answer</summary>

**Bugs found:**

1. **Data leakage (critical):** `StandardScaler` is fit on the entire dataset (line 9-10) BEFORE the train/test split (line 12). The scaler learns mean/std from test data, leaking information into training. Fix: split first, then `scaler.fit(X_train)` and `scaler.transform(X_test)`.

2. **Missing import:** `LogisticRegression` is used but never imported. Add `from sklearn.linear_model import LogisticRegression`.

3. **Evaluating on training data (line 16):** `model.score(X_train, y_train)` reports training accuracy, which will be optimistically biased. Should evaluate on `X_test, y_test` for an honest generalization estimate.

4. **No stratification:** If the target is imbalanced, `train_test_split` without `stratify=y` may create folds with different class distributions. Add `stratify=y`.

**Verdict:** The code would run after adding the import (if target is numeric), but the leakage bug means reported performance would be unreliable and overly optimistic.

</details>

### Mock Q3: Write Code (Coding)

**Prompt:** Read a file `input.txt` where each line has a number and a word separated by a tab. Extract the word from lines where the number is a perfect square. Print the words joined by spaces.

**Input file:**
```
1	hello
3	world
4	test
9	foo
10	bar
16	baz
```

**Expected output:** `hello test foo baz`

<details>
<summary>Gold-standard solution</summary>

```python
import math

def is_perfect_square(n):
    if n < 0:
        return False
    root = int(math.isqrt(n))
    return root * root == n

words = []
with open("input.txt", "r") as f:
    for line in f:
        line = line.strip()
        if not line:
            continue
        parts = line.split("\t")
        if len(parts) != 2:
            continue
        number = int(parts[0])
        word = parts[1]
        if is_perfect_square(number):
            words.append(word)

print(" ".join(words))
```

**Explanation:** I read the file line by line, split each line by tab to separate the number and word. I check if the number is a perfect square using `math.isqrt()` (integer square root) — a number is a perfect square if `isqrt(n) ** 2 == n`. I collect matching words and join them with spaces. Edge cases handled: empty lines, negative numbers (not perfect squares), malformed lines with wrong number of fields.

</details>

<summary>Gold-standard answer</summary>

**Verdict: False.**

The claim confuses flexibility with performance. Python lists store references to Python objects, requiring type checking and boxing for each element. NumPy arrays store homogeneous data in contiguous memory blocks, enabling vectorized operations implemented in C. For numerical computations (arithmetic, matrix operations, aggregations), NumPy arrays are typically 10–100x faster than Python lists due to: (1) no per-element type checking, (2) contiguous memory layout enabling CPU cache efficiency, (3) SIMD vectorization, and (4) operations delegated to optimized BLAS/LAPACK libraries. Python lists are more flexible (heterogeneous types, dynamic resizing) but this flexibility comes at a significant performance cost. The statement reverses the actual performance relationship.

</details>

## 17. Troubleshooting FAQ

### Application & assessment

**Q: I failed the assessment. Can I retake?**  
A: No. One attempt per track. Try a different track (Generalist) or a different platform (Mercor, Alignerr).

**Q: It's been 2 weeks with no response. Am I rejected?**  
A: Likely yes, though some report approval at 2 weeks. If 4+ weeks with "Check back soon" → move on.

**Q: Can I use GitHub Copilot in VS Code during assessment?**  
A: No. Any AI assistance is prohibited during assessment.

**Q: The coding test says to use my local environment. Is that normal?**  
A: Yes. Write code locally, test it, then paste/submit on the platform.

### Payments

**Q: I only have Indian PAN and bank account. Can I get paid?**  
A: Yes — via PayPal. Link bank to PayPal. DA does not pay bank directly.

**Q: How long until first payment?**  
A: 1–2 weeks after your first approved task.

**Q: PayPal is asking for business proof. What do I provide?**  
A: Select "Individual/Freelancer" if no registered business. PAN + Aadhaar is usually sufficient.

**Q: My PayPal payment is on hold. What do I do?**  
A: Complete all KYC steps in PayPal notification center. Ensure PAN-Aadhaar linked.

### Work availability

**Q: I passed but no projects appear. Normal?**  
A: Yes. Wait 1–4 weeks. Apply to Mercor/Alignerr in parallel.

**Q: Projects disappeared after weeks of work. What happened?**  
A: Project ended or budget exhausted. Check dashboard for new projects regularly.

**Q: My task was rejected. Do I get paid?**  
A: No payment for rejected tasks. Learn from feedback and improve.

### Technical

**Q: Persona ID verification failed. Tips?**  
A: Good lighting, no glasses, no VPN, use phone camera, try passport if Aadhaar fails.

**Q: Assessment page froze. What do I do?**  
A: Don't refresh if possible. Contact support via dashboard. If lost, you may need to restart (check if progress saved).
